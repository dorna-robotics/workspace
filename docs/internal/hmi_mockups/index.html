MOCKUPSHMI

Pendant HMI — sample templates

Static mockups with fake data, styled on the platform's design tokens. All monitoring content shown would be declared per project in hmi.j2 (widgets bound to facts / rt.op values) and rendered by the platform. All variants share: 4 control tiles on ONE line, operator language, no debug text.

A — Headline
Big state line + progress bar + stat tiles. The minimal, universal layout.
B — Rack-centric
The rack map is the hero: per-slot state colored from facts. Most "lab HMI" of the three.
C — Split dashboard
Progress ring + state left, stat grid right, alert banner. Shown in PAUSED state.
F — Bench map (auto-generated)
SUBWAY MAP: uniform station cards spatially arranged from the scene, slot dots colored by facts, rail bar with live carriage. Schematic for state; the 3D view keeps realism.
G — Guided recovery
Something's wrong: one sentence, one fix button (bound to an operator action), Resume unlocks after. Attention screen, not a dashboard.
E — Widget gallery
The full expandable catalog: state, stat, timer, progress, ring, gauge, rack, alert, devices, checklist, trend, camera, scan, queue, keyval.
D — Parameters as run setup
Preset cards + touch stepper / segmented / toggle instead of the tiny form.
H — Working rack, full state grammar (site-visit input)
Per-slot live states incl. barcode-failed (amber, tap → rescan/skip popover), skipped, queued, empty. Two racks + legend.
J — Master–detail rack (alternate pattern)
The self-critique of H: 5 states max + icon redundancy, persistent detail panel instead of popovers (touch + 96-well scale), grid ⇄ table toggle for values/barcodes.
I — Load racks: pick positions on screen (site-visit input)
Run setup: tap which positions to process — writes in_1/in_2 kwargs. Quick actions, capacity check, Start.
